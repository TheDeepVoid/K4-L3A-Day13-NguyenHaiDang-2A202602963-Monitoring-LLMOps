# CP1 - STRUCTURED LOG EVIDENCE (request_received, response_sent, request_failed)
#
# Two POST /chat calls: one that succeeds, one that fails, so all three event
# types appear. The correlation_id is generated in the middleware (or taken from
# an inbound x-request-id), bound once, and shared by every line of that request;
# the request context (user_id_hash, session_id, feature, model, env) is bound in
# the handler before the first line is written.

## Response headers (the id is returned to the caller, not only logged)
$ curl -sD - -X POST http://127.0.0.1:8000/chat -H 'x-request-id: upstream-demo-01' ...

  x-request-id: upstream-demo-01
  x-response-time-ms: 153.65
