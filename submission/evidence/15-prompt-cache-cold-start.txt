# PREVENTIVE MEASURE 2 - the cold-start prompt fetch
#
# Found while collecting final numbers: p50 had jumped from 150 ms to 898 ms
# with no errors and no incident. The cause was not the service. The first
# requests after a restart miss the Langfuse prompt cache, so resolve_prompt
# performs a synchronous HTTPS call to Langfuse inline in the request path.
#
# It was invisible for a second reason: the fetch sat between the retrieval
# and generation spans, outside every observation, so no span accounted for
# the extra 750 ms. The trace said 2 spans totalling 300 ms while the log said
# 900 ms - the two signals disagreed and neither was obviously wrong.
#
# Fixes: a resolve-prompt span so the dependency is part of the tree, and a
# warm_prompt_cache() call in the FastAPI lifespan so the first user request
# does not pay for someone else's cold cache.
